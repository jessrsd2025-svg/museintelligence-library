## 1. Executive summary


`ARXIV-MD-INGEST-V1` gives authorized agents and analysts a governed search engine for public research and approved organizational data.


The system:


1. Retrieves metadata and PDF source objects from arXiv and other allowlisted public repositories.
2. Stores original source bytes as immutable or retention-locked objects.
3. Computes source-level cryptographic digests.
4. Converts papers into provenance-bearing Markdown.
5. Preserves section, page, equation, figure, table, and citation locators.
6. Registers metadata, claims, lineage, and review state in D1.
7. indexes derived chunks in Vectorize or another approved vector store.
8. Provides GraphRAG retrieval without treating similarity as corroboration.
9. Routes proposed claims and relationships through the AEQUITAS Silent-Upgrade Interdiction Gate.
10. Exposes approved lineage relationships to Neo4j through a restricted mutation service.
11. Isolates prediction-market data as `PROBABILISTIC_SIGNAL` and `SENTIMENT_ONLY`.
12. Requires human review before epistemic promotion, repository publication, or high-impact downstream use.


The design is LLaMA-aware but not LLaMA-dependent. It records model family, tokenizer, context window, prompt contract, and generation parameters so that retrieval and evaluation can be reproduced across open and commercial models.

## 2. Problem statement(ARXIV-MD-INGEST-V1), the AEQUITAS Silent-Upgrade Interdiction Gate enforces a deterministic policy engine designed to prevent provenance loss and silent epistemic promotion. It ensures that unverified machine outputs are never treated as validated facts.


The gate applies the following deterministic rules, blocked transitions, and routing outcomes:


1. Blocked Epistemic Transitions


The gate explicitly prevents unverified, automated, or statistical markers from upgrading themselves to authoritative data types:


- **Source assertion** \(\rightarrow \) Blocked from becoming a **Verified fact**.
- **Similarity score** \(\rightarrow \) Blocked from being treated as **Corroboration**.
- **Citation repetition** \(\rightarrow \) Blocked from implying **Source independence**.
- **Entity mention** \(\rightarrow \) Blocked from establishing **Identity resolution**.
- **Graph proximity** \(\rightarrow \) Blocked from inferring **Causality**.
- **Prediction-market price** \(\rightarrow \) Blocked from certifying an **Event occurrence**.
- **Model confidence** \(\rightarrow \) Blocked from reflecting **Evidence confidence**.
- **Generated summary** \(\rightarrow \) Blocked from serving as **Source evidence**.
- **Agent consensus** \(\rightarrow \) Blocked from constituting **Independent verification**.


2. Deterministic Quarantine Triggers


The TypeScript gate function (`adjudicateProposal`) strictly intercepts and evaluates incoming analytical proposals. A proposal is immediately routed to **Quarantine** (`quarantine.md`) under any of the following conditions:


- **Missing Provenance:** The proposal lacks a valid `sourceId` or `sourceLocator` (`INCOMPLETE_PROVENANCE`).
- **Unsubstantiated Similarity:** The proposal is derived from semantic similarity rather than verified text (`SIMILARITY_IS_NOT_CORROBORATION`).
- **Market Signal Corruption:** The proposal attempts to confirm a real-world event using speculative prediction-market data (`MARKET_SIGNAL_IS_NOT_EVENT_EVIDENCE`).
- **Synthetic Evidentiary Basis:** The proposal relies on an LLM-generated summary instead of direct source material (`GENERATED_SUMMARY_IS_NOT_SOURCE_EVIDENCE`).
- **Model Score Reliance:** The proposal treats an arbitrary model score as factual confidence (`MODEL_SCORE_IS_NOT_EVIDENCE_CONFIDENCE`).
- **Machine Consensus Hallucination:** The proposal tries to establish truth via multi-agent agreement alone (`CONSENSUS_IS_NOT_VERIFICATION`).
- **Prohibited Relationships:** The proposal contains a relationship restricted by system policy (`PROHIBITED_CAUSAL_RELATIONSHIP`).
- **Unverified Promotion:** The proposal requests an epistemic upgrade without a proper transaction trail (`SILENT_EPISTEMIC_UPGRADE`) or lacks human signature approval (`HUMAN_DISPOSITION_REQUIRED`).


3. Target Routing and Downstream Actions


When a proposal passes all programmatic checks, it returns a status of `ALLOW_PENDING_TRANSACTIONAL_VALIDATION` but keeps graph mutations disabled (`graphMutationAuthorized: false`). Permanent promotion or structural changes to downstream knowledge bases—such as writing to a **Neo4j Lineage Graph**—require a separate, human-signed review disposition. Direct write access by reasoning agents is strictly prohibited to keep the analytical loop safe from unauthorized edits.


Research-ingestion systems commonly collapse several distinct objects into one:


- the original PDF;
- extracted text;
- reconstructed Markdown;
- OCR corrections;
- generated summaries;
- embeddings;
- model interpretations;
- approved knowledge.


This creates provenance loss and silent epistemic promotion.


`ARXIV-MD-INGEST-V1` maintains explicit boundaries:


```
Original source  → extracted representation  → retrieval object  → analytical proposal  → review disposition  → governed knowledge object
```


Neither extraction, semantic similarity, model consensus, nor database registration establishes factual verification.

## 5. Technical corrections and invariants


### Cryptographic anchoring


The source digest is calculated from the exact downloaded source bytes.


```
PDF bytes → SHA-256 → source_sha256
```


RFC 8785 canonicalization applies to a JSON manifest, not directly to arbitrary Markdown:


```
Metadata + lineage + artifact digest  → canonical JSON manifest  → RFC 8785 canonicalization  → SHA-256  → manifest_sha256
```


The Markdown receives a separate byte-level digest:


```
UTF-8 Markdown bytes → SHA-256 → artifact_sha256
```

## 7. LLaMA-aware model abstraction


The ingestion pipeline must not assume that one tokenizer, context window, or instruction format applies to every LLaMA-family deployment.


```
model_profile:  profile_id: LLAMA-PROFILE-EXAMPLE  provider: APPROVED_PROVIDER  model_family: LLaMA  model_identifier: PINNED_MODEL_ID  model_revision: PINNED_REVISION  tokenizer_identifier: PINNED_TOKENIZER  context_window: CONFIGURATION_REQUIRED  quantization: NONE_OR_DECLARED  system_prompt_hash: REQUIRED  task_contract_hash: REQUIRED  temperature: 0  tool_access: NONE_BY_DEFAULT  private_reasoning_storage: prohibited
```


### LLaMA-specific controls


- Chunk sizing is based on the deployed tokenizer rather than character count.
- Retrieval context reserves capacity for citations, policy instructions, and dissent.
- Source IDs and locators cannot be removed during context compression.
- Model-generated summaries are stored separately from extracted passages.
- Model rejection is a review result, not proof that a paper is invalid.
- A model cannot approve its own permanent-memory update.
- Model revisions require regression evaluation before production use.


The repository should use `rejected.md`, not `llama-rejection.md`, as the canonical disposition. A compatibility alias may be retained:


```
llama-rejection.md → rejected.md
```


This avoids encoding one model family into the governance taxonomy.

## 8. Paper-routing policy


### Accepted


A paper may enter the reviewed repository when:


- metadata is complete;
- source bytes were retrieved;
- the source digest was computed;
- the extractor version is pinned;
- required locators were preserved;
- Markdown passed structural validation;
- licensing and usage conditions were recorded;
- no unresolved security finding blocks publication;
- the human disposition authorizes publication.


### Quarantined


Route to `quarantine.md` when:


- metadata is incomplete;
- the PDF cannot be parsed reliably;
- source and derived hashes are missing;
- source locators were lost;
- OCR confidence falls below policy;
- citations are malformed or unresolved;
- the document contains prompt-injection content;
- classification is ambiguous;
- a generated summary is presented as source text;
- a proposed claim relies only on semantic similarity.


### Rejected


Route to `rejected.md` when:


- the source falls outside approved scope;
- it is a duplicate or superseded version;
- the source violates repository policy;
- licensing prohibits the intended storage or transformation;
- malware or active content is detected;
- the source fails an authorized security review;
- a human reviewer rejects the ingestion request.

## 7. LLaMA-aware model abstraction


The ingestion pipeline must not assume that one tokenizer, context window, or instruction format applies to every LLaMA-family deployment.



### LLaMA-specific controls


- Chunk sizing is based on the deployed tokenizer rather than character count.
- Retrieval context reserves capacity for citations, policy instructions, and dissent.
- Source IDs and locators cannot be removed during context compression.
- Model-generated summaries are stored separately from extracted passages.
- Model rejection is a review result, not proof that a paper is invalid.
- A model cannot approve its own permanent-memory update.
- Model revisions require regression evaluation before production use.


The repository should use `rejected.md`, not `llama-rejection.md`, as the canonical disposition. A compatibility alias may be retained:


```
llama-rejection.md → rejected.md
```


This avoids encoding one model family into the governance taxonomy.

## 8. Paper-routing policy


### Accepted


A paper may enter the reviewed repository when:

Route to `quarantine.md` when:


- metadata is incomplete;
- the PDF cannot be parsed reliably;
- source and derived hashes are missing;
- source locators were lost;
- OCR confidence falls below policy;
- citations are malformed or unresolved;
- the document contains prompt-injection content;
- classification is ambiguous;
- a generated summary is presented as source text;
- a proposed claim relies only on semantic similarity.


### Rejected


Route to `rejected.md` when:


- the source falls outside approved scope;
- it is a duplicate or superseded version;
- the source violates repository policy;
- licensing prohibits the intended storage or transformation;
- malware or active content is detected;
- the source fails an authorized security review;
