not establish actor attribution. Commercial cover, dual-use infrastructure, incomplete
source lineage, repeated dependent reporting, and temporal ambiguity must be modeled
explicitly.

targeting, autonomous enforcement, or speculative actor designation.

Approved only within an access-controlled and audited workspace. Exports require
human review and a provenance bundle.

No observation may become an accepted assessment until its source page, extraction,
canonical object, digest, graph relationships, and review state are registered.

## Chunking policy


1. Preserve page boundaries.
2. Preserve section headings.
3. Keep tables with their headers.
4. Do not combine unrelated claims.
5. Retain attribution language such as “reported,” “alleged,” or “assessed.”
6. Keep geographic coordinates with their feature description.
7. Retain preceding and following chunk links.
8. Generate a digest for every chunk.
9. Record transformations from OCR to normalized text.
10. Never treat retrieval rank as evidence strength.


## Recommended chunk classes


| Class | Content |
| --- | --- |
| `SOURCE_TEXT` | Faithful extracted text |
| `TABLE` | Table with headers and source page |
| `IMAGE_CAPTION` | Image description and page locator |
| `CLAIM` | One or more closely related source assertions |
| `GEOFEATURE` | Location, geometry, and spatial context |
| `ARCHITECTURE` | Technical system or pipeline description |
| `ASSESSMENT` | Analyst judgment, clearly labeled |
| `POLICY` | Constraint, authorization, or governance statement |
