# 🤖 LIBERTAS Agent Roles Index


## 🌐 Integrated Analytical Environment
The `LIBERTAS v6.0` framework defines a conceptual analytical environment bringing together geospatial observations, infrastructure data, documentary evidence, and graph relationships within a provenance-aware knowledge fabric[cite: 7].


Cartography functions as an evidence fabric rather than a passive representation of physical borders[cite: 7]. —


## ⚔️ Multi-Agent Consensus Model


Decision-making within the **American Science Cloud (AmSC)** is structured as a controlled contest among specialized agents[cite: 7]. Before an intent state is pushed to execution, each sub-agent audits the proposal from its distinct operational boundary[cite: 7]:


### 👥 Specialized Agent Registry


* `Proposer Agents` — Generates alternative remediation strategies and candidate action plans[cite: 7].


* `Critic Agents` — Stresses plans to identify risks, hidden assumptions, intelligence gaps, and likely cascade failure modes[cite: 7].


* `Policy Agents` — Conducts automated compliance validations against systemic constraints and frameworks (e.g., NIST 800-53)[cite: 7].


* `Security Agents` — Evaluates user authorizations, cross-domain access conditions, and tactical operational safeguards[cite: 7].


* `Provenance Agents` — Validates ledger lineage, data source attribution, and unbroken cryptographic traceability[cite: 7].


* `Cost/Lag Agents` — Assesses performance efficiency, operational resource overhead, and processing latency parameters[cite: 7].


* `Human Review Agents` — Acts as a safe boundary, escalating high-risk, ambiguous, or critical anomalies for analyst oversight[cite: 7].


* `Consensus Engine` — Synthesizes multi-agent input to select, reject, or return plans to the proposer queue for active revision[cite: 7].


—


## ⚡ Consensus Flow Pipeline


The progression from unverified raw telemetry to validated execution intent strictly follows this deterministic routing path[cite: 7]:


[ Structured Context ] ──► [ Candidate Plans ] ──► [ Critic Review ] │ ▼ [ Provenance Validation ] ◄── [ Security Validation ] ◄── [ Policy Validation ] │ ▼ [ Consensus ] ──► [ Human Interrupt Gate ] ──► [ Validated Intent Execution ]


—


## 🛠️ ACT — Deterministic Execution Layer


Once the **Human Interrupt Gate** passes validated intent out of the consensus cycle, execution is delegated to deterministic action components that translate strategic intent into auditable operations[cite: 7]:


* **Tool Agents:** Executing target-scoped terminal queries or environment sweeps[cite: 7].


* **API Workers:** Dispatching state changes across authenticated edge routers[cite: 7].


* **n8n Action Nodes:** Triggering automated orchestration playbooks with fixed execution IDs[cite: 7].

**# Systemic Failure Modes**


**## 1. Orientation Drift (Feedback Loops)**


System logs its own action’s side effects as unrelated external events →


recursive loop, “reacting to its own shadow.”


**Fix:** Pair every action with an execution ID in the provenance graph.


**## 2. Latent-Space Hallucination**


Orient phase relies on LLM alone → interpretation by statistical weights


rather than operational axioms.


**Fix:** Deterministic knowledge graph grounding ([[Orient_GraphRAG_Context]]).


**## 3. Cascading Cascades**


No explicit state-machine validation between Decide and Act →


failures cascade across topologies faster than operators can respond.


**Fix:** Validated intent gate + [[Human_Review_Gates]].

## Agentic OODA Deterministic Phase (ACT) — Multi-Agent Consensus


### Context


The Agentic OODA framework is designed to support mission-critical decision-making through a structured, autonomous workflow. The deterministic ACT phase is crucial for executing validated decisions.


### Reasoning Levels


The reasoning levels are defined as follows:


1. **Light**: Basic analysis and straightforward decision-making.
2. **Medium**: Moderate complexity analysis, requiring some integration of multiple factors.
3. **High**: Complex analysis involving multiple variables and nuanced decision-making.
4. **Extra**: Highly complex scenarios necessitating advanced analytical capabilities and potentially multiple iterations.
5. **Ultra**: Extremely complex tasks that require spawning sub-agents to break down the task into parallel subtasks.


### Task Assignment


For the deterministic ACT phase, specifically during the `Decide_Multi_Agent_Consensus` stage, we will utilize the **Multi-Agent Consensus Model**.


### Decision Model: Multi-Agent Consensus Model


The Multi-Agent Consensus Model involves a structured contest among specialized agents to evaluate proposed actions. Each agent brings a unique perspective or expertise to the decision-making process.


#### Agent Roles


1. **Proposer Agent**: Generates candidate plans or responses.
2. **Critic Agent**: Identifies risks, contradictions, and unsupported assumptions.
3. **Policy Agent**: Checks compliance with applicable constraints and regulations.
4. **Security Agent**: Evaluates access, authorization, and operational safeguards.
5. **Provenance Agent**: Validates the lineage and source sufficiency of evidence.
6. **Cost/Latency Agent**: Assesses operational efficiency, resource cost, and latency.
7. **Human Review Agent**: Routes high-risk or uncertain decisions for analyst oversight.


### Operation


1. **Structured Context**: The Orient phase provides a structured situation model.
2. **Candidate Plans**: The Proposer Agent generates candidate plans.
3. **Critic Review**: The Critic Agent reviews plans for risks and assumptions.
4. **Policy Validation**: The Policy Agent checks plans against applicable policies.
5. **Security Validation**: The Security Agent evaluates plans for security and authorization.
6. **Provenance Validation**: The Provenance Agent verifies the evidence lineage.
7. **Consensus Scoring**: The system scores the consensus among agents.
8. **Human Interrupt**: If necessary, high-risk decisions are routed for human review.


### Reasoning Level Escalation


For the `Decide_Multi_Agent_Consensus` task:


- Start with **Light** reasoning for straightforward decisions.
- Escalate to **Medium** for decisions requiring moderate complexity analysis.
- Use **High** for complex decisions involving multiple variables.
- **Extra** may be necessary for highly complex scenarios.
- **Ultra** will be employed for extremely complex tasks, spawning sub-agents as needed.
