# Agentic OODA Overview

The analytical workflow is organized around an iterative Observe–Orient–Decide–Act cycle.

```text
OBSERVE
    │
    ▼
ORIENT
    │
    ▼
DECIDE
    │
    ▼
ACT
    │
    ▼
REVIEW
    │
    ▼
KNOWLEDGE UPDATE
````


## Agentic Translation


| OODA Phase | MAS Component | Orchestration Function | Provenance Requirement |
| --- | --- | --- | --- |
| Observe | Listener agents, webhook nodes, telemetry collectors | Capture external and internal events | Timestamp, source ID, digest, execution context |
| Orient | GraphRAG agents, embedding engines, Neo4j graph | Contextualize observations | Link to prior nodes, policies, entities, relationships |
| Decide | Proposer, critic, validator, compliance agents | Generate and evaluate possible actions | Store candidate plans, rejected paths, rationale |
| Act | Tool agents, API workers, n8n action nodes | Execute approved action | Execution ID, action hash, rollback state |
| Feedback | State probe agents, monitoring hooks | Observe effects of action | Correlate side effects to originating execution ID |


## Key Principle


No action should proceed from decision to execution unless the intent object has:


- Provenance
- Policy clearance
- Security validation
- Review status
- Execution trace metadata

# Observe — Event Ingestion and Provenance Tracking

In a human system, observation depends on perception.

In a multi-agent system, observation depends on structured event capture.

## Input Sources

- Webhooks
- API events
- Kafka topics
- n8n triggers
- Filesystem watchers
- Database change streams
- Sensor telemetry
- Log streams
- Human-submitted reports
- Scheduled polling jobs

## Problem

Raw events are not trustworthy by default.

Therefore, every observation must enter the system as a claim requiring lineage.

## Observe Layer Pipeline

```text
Event Source
    ↓
Ingestion Listener
    ↓
Schema Validation
    ↓
Timestamping
    ↓
Canonicalization
    ↓
SHA-256 Digest
    ↓
Observation Node
    ↓
Graph Registration
````

## Doctrinal Rule

# Orient — GraphRAG Context and Semantic Orientation

Orientation is the most difficult phase to automate.

This phase converts:

```text
Raw telemetry → Structured context
````


## Orientation Components


A resilient orientation layer combines:


- Vector embeddings
- Knowledge graphs
- Deterministic rules
- Policy constraints
- Historical state
- Entity resolution
- Temporal reasoning
- Confidence scoring
- Human-defined axioms


## Orient Layer Architecture


```
Observation Node    ↓Entity Extraction    ↓Vector Embedding    ↓Semantic Retrieval    ↓Neo4j Graph Expansion    ↓Policy Context Retrieval    ↓Temporal Alignment    ↓Structured Situation Model
```


## GraphRAG Orientation Pattern


```
New Observation    ↓Embed observation text and metadata    ↓Retrieve semantically similar prior records    ↓Resolve entities and locations    ↓Traverse graph relationships    ↓Compare against policies and known constraints    ↓Generate orientation package
```


## Orientation Package Schema


```
{  "orientation_id": "orient_20260705_000001",  "observation_id": "obs_20260705_000001",  "entities": [    {      "entity_id": "entity_001",      "label": "InfrastructureNode",      "confidence": 0.82    }  ],  "related_graph_nodes": [    "GeoFeature_REDSEA_LAYER_001",    "Policy_ZERO_TRUST_001",    "Assessment_SUPPLY_CHAIN_RISK_004"  ],  "semantic_neighbors": [    {      "document_id": "doc_001",      "similarity": 0.91    }  ],  "policy_constraints": [    "human_review_required",    "no_unverified_external_action",    "provenance_required"  ],  "orientation_summary": "Observation appears related to existing maritime infrastructure analysis layer and requires review before action.",  "confidence": 0.74}
```


## Key Risk: Latent-Space Hallucination


If orientation is performed only by an LLM, the system may create plausible but unsupported explanations.


### Failure Mode


```
Observation    ↓LLM interpretation without graph grounding    ↓Confident but unsupported conclusion    ↓Bad decision
```


### Fix


```
Observation    ↓GraphRAG orientation    ↓Policy constraints    ↓Source-linked evidence    ↓LLM summary with citations to graph nodes
```


## Doctrinal Rule


> The language model may explain the graph.
> It must not replace the graph.

# Mission-Critical Decision Technical Mapping

This note maps the Agentic OODA architecture into a mission-critical decision support workflow.

## Decision Pipeline

```text
Observation Received
    ↓
Provenance Verified?
    ├── No → Quarantine / Exclude from trusted graph
    └── Yes
          ↓
GraphRAG Orientation
          ↓
Policy Constraints Applied
          ↓
Candidate Plans Generated
          ↓
Critic / Security / Provenance Validation
          ↓
Risk State Assigned
          ↓
Human Review Gate if Required
          ↓
Validated Intent
          ↓
Deterministic Execution
          ↓
Feedback Probe
          ↓
Knowledge Update
````


## Decision Gates


| Gate | Question | If Failed |
| --- | --- | --- |
| Provenance Gate | Is the observation traceable? | Quarantine |
| Orientation Gate | Is the context graph-grounded? | Re-orient |
| Policy Gate | Does the plan satisfy constraints? | Reject or revise |
| Security Gate | Is the action authorized and bounded? | Block |
| Human Review Gate | Is risk above threshold? | Escalate |
| Execution Gate | Is rollback state available? | Pause |
| Feedback Gate | Are side effects correlated to execution ID? | Investigate |


## Risk States


| State | Meaning | Action |
| --- | --- | --- |
| Traceable | Provenance intact and orientation stable | Continue |
| Human Review Required | Uncertainty or policy sensitivity present | Escalate |
| Cascade Risk | System may react to its own outputs | Freeze action |
| Broken Lineage | Missing source, digest, or review state | Exclude from graph |

# Agentic OODA Failure Modes

## 1. Orientation Drift

### Description

The system misclassifies its own action side effects as unrelated external events.

### Failure Pattern

```text
Action
    ↓
Side Effect
    ↓
Observe as New External Event
    ↓
Incorrect Orientation
    ↓
Recursive Response
````


### Fix


Pair every action with:


- Execution ID
- Action hash
- Rollback state
- Feedback correlation ID


## 2. Latent-Space Hallucination


### Description


The Orient phase relies only on LLM-generated interpretation without deterministic graph grounding.


### Fix


Require:


- GraphRAG orientation
- Policy constraints
- Source-linked evidence
- Citations to graph nodes


## 3. Cascading Cascades


### Description


The system moves too quickly from Decide to Act without state-machine validation.


### Fix


Require:


- Consensus scoring
- Policy validation
- Security validation
- Human interrupt for high-risk actions
- Rollback state


## 4. Broken Provenance


### Description


Observation enters the graph without source metadata, digest, timestamp, or review state.


### Fix


Quarantine object until provenance requirements are satisfied.


## 5. Review Bypass


### Description


High-risk outputs proceed to execution without analyst approval.


### Fix


Hard policy gate:


```
if risk_state = high:    require human_review
```
