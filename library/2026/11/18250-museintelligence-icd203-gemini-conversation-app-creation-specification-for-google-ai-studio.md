## Purpose


The MuseIntelligence ICD203 app is a reading-room and governance app for the LIBERTAS // VERITAS // AEQUITAS system. It ingests documents (PDFs) and shared AI conversations, renders them as a browsable markdown wiki/index, and governs every claim in them with provenance, epistemic tags, and the 18-gate acceptance checklist. Nothing in the app is presented as settled fact unless a human has reviewed its source. The app’s reasoning engine is an open-source, open-weights model served from Hugging Face (§3); no proprietary model is the app’s engine.


*Sources: `SRC-GEMINI-ICD203-2026-11-23` — epistemic tag: SOURCE_REPORTED.*


## Architecture


The app is built around the Observe–Orient–Decide–Act (OODA) loop:


- **Observe** — ingest source material (PDFs, shared AI conversations) and register every source object with its provenance.
- **Orient** — place each claim against the governance precedence hierarchy (§4) and the reasoning modes (§6).
- **Decide** — run the AEQUITAS gates and the interdiction triggers (§5); halt any claim a trigger fires on.
- **Act** — publish only gated output: renderings, indexes, and quarantine views.


The app also follows the Capture → Analyze → Strategize → Execute pipeline: capture source material, analyze it into governed claims, strategize the rendering, and execute the build. The OBSERVE panel (§7) supplies the observation tools, and the 18-gate acceptance checklist (§11) is the decision gate for everything the app ships.


*Sources: `SRC-GEMINI-ICD203-2026-11-23` — epistemic tag: SOURCE_REPORTED.*


## Runtime model — open-source backend


The app’s AI backend is an open-source, open-weights model. No proprietary model serves as the app’s engine. Google AI Studio is the build environment only; the model below is what the finished app runs.


- **Default model:** `Qwen/Qwen2.5-7B-Instruct` — an instruction-tuned 7B open-weights model (7.61B parameters, 131,072-token context, Apache License 2.0, ungated on Hugging Face), verified to exist on Hugging Face 2026-11-25. Its model card reports strengths in instruction following, understanding structured data, and generating structured outputs (JSON) — the app’s core work of document reasoning, structured extraction, and checklist evaluation. The 7B class fits the app’s hosting; the card recommends serving with vLLM or Hugging Face Transformers.
- **Selection criteria (for the default or any replacement):** an instruction-tuned open-weights model suited to document reasoning, structured extraction, and checklist evaluation; a license permitting the app’s use (a permissive open license such as Apache 2.0); small enough to run in the app’s hosting (7B class); ungated on Hugging Face.
- **Pinning (build time).** The model is served from Hugging Face and pinned to an immutable commit SHA — never a floating branch or tag — the same rule as TOOL-GH-01 / gate A3. At build time the SHA is resolved and pinned via the TOOL-GH-01 flow (`pin_commit_sha` to resolve the ref, `verify_ref` to check it), recorded in the app configuration, and the app loads weights only at that pinned SHA. A tag may be used only as the input to the pin step; the app never loads weights by a branch name or a tag. The pinned commit SHA for this build is: *to be pinned at build time*. No SHA is stated here — none was resolved at writing time, and inventing one would violate the provenance rules.
- **The model is a reasoning engine only.** It never assigns VERIFIED_FACT; its outputs are SOURCE_REPORTED / GENERATED_ANALYSIS until a human reviews them. The governance precedence hierarchy (§4) places model preference last: the model never overrides policy, the AGENTS.md specification, a gate, a task contract, or a dispatch.

## Features to build


1. **Document ingest and rendering.** Accept PDFs and shared AI conversations (Gemini shares, ChatGPT shares) and render them as a markdown wiki/index in the Renderings.md canonical format, with source references and an index with anchors.
2. **Provenance display.** Every claim shows its source_id, source_locator, and retrieval_timestamp. Claims without complete provenance are flagged INCOMPLETE_PROVENANCE.
3. **Quarantine view.** Non-evidentiary claims — similarity-only matches, market signals, generated summaries — are shown in a quarantine view, never mixed into the verified record. The RubyGems finding (§12) is the example item.
4. **18-gate acceptance checklist runner.** Run `tools/aequitas_gate_linter.py` over the app’s artifacts and show PASS, FAIL, or MANUAL per gate.
5. **Market-sentiment envelope viewer.** Display `templates/06_market_sentiment_envelope.json` envelopes with the SENTIMENT_ONLY guard: implied probabilities are sentiment only, graph_mutation_authorized is false, human_review_required is true, and confidence_weight is 0.0.


*Sources: `SRC-GEMINI-ICD203-2026-11-23`, `SRC-ICD203-RENDERING-2026-11-23` — epistemic tag: SOURCE_REPORTED.*


## GitHub tool integration — TOOL-GH-01


All GitHub reads in the app go through TOOL-GH-01, implemented in `tools/github_call.py`. The module exposes four operations:


- `pin_commit_sha(repo, ref)` — resolve a ref (tag or commit SHA) to its 40-hex commit SHA via the public GitHub API.
- `verify_ref(repo, ref, expected_sha)` — resolve a ref and, when an expected SHA is given, check the resolved SHA equals it.
- `fetch_bytes_at_sha(repo, sha, path)` — return the raw bytes of a file at a pinned commit SHA.
- `hash_bytes(data)` — return the SHA-256 hex digest of bytes.


Rules for the app: fetch only at pinned 40-hex commit SHAs; never fetch from an unpinned ref; never trust a branch HEAD. Branch names (main, master, HEAD) are refused. The invariant is: commit_sha is the anchor; branch names are not. Reads use the public GitHub API without authentication; a GITHUB_TOKEN may be supplied to raise the rate limit, but it is never required.


*Sources: `SRC-GEMINI-ICD203-2026-11-23`, `SRC-ICD203-RENDERING-2026-11-23` — epistemic tag: SOURCE_REPORTED.*
