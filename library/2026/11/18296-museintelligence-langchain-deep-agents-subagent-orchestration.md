The MuseIntelligence ICD203 app needs an orchestration layer for long-horizon, multi-step work: planning a task, delegating parts of it to subagents with isolated context, keeping working memory in files instead of the message history, and pausing for human approval before anything irreversible happens. LangChain’s Deep Agents is an open-source, MIT-licensed agent harness that supplies exactly those four patterns out of the box — planning, filesystem, subagent delegation, and context management — on top of LangGraph. This proposal wires that harness into Muse / LIBERTAS as the orchestration layer, under AEQUITAS governance: the harness runs the loop, the gates decide what may be promoted, and the human supervisor signs off. Nothing in the harness overrides policy, the AGENTS.md specification, a gate, a task contract, or a dispatch.


*Sources: `SRC-DEEPAGENTS-GH-2026-11-26`, `SRC-APP-SPEC-2026-11-25` — epistemic tag: SOURCE_REPORTED.*


## Architecture — OODA over the Deep Agents harness


The integration is built around the Observe–Orient–Decide–Act (OODA) loop, with each phase mapped onto a Deep Agents capability:
- **Observe** — ingest source material and read the working state: the filesystem tools (`ls`, `read_file`, `grep`), the OBSERVE panel tools (§7), and the Neo4j repository-map graph context (§10) as an SVG rendering plus a structured node/edge list.
- **Orient** — place each claim against the governance precedence hierarchy (§4) and the reasoning modes (§6); the Neo4j graph context shows where the task sits in the repository map, and the memory middleware loads AGENTS.md as cross-session memory.
- **Decide** — run the AEQUITAS gates and the interdiction triggers (§5) as a deterministic gate middleware; the planning tool (`write_todos`) breaks the task down and tracks progress; the human-in-the-loop interceptor pauses for human sign-off (gate E3) and for context-vs-authorization separation (gate D2).
- **Act** — publish only gated output: subagents execute their contracted subtasks through the `task` tool, filesystem writes go through the gate middleware, and renderings, indexes, and quarantine views are the only shipped artifacts.


The harness is a compiled LangGraph graph (`CompiledStateGraph`), so streaming, checkpointing, interrupts, and time-travel still apply. The app also follows the Capture → Analyze → Strategize → Execute pipeline: capture source material, analyze it into governed claims, strategize the rendering, and execute the build. The OBSERVE panel (§7) supplies the observation tools, and the 18-gate acceptance checklist (§13) is the decision gate for everything the app ships.


*Sources: `SRC-DEEPAGENTS-GH-2026-11-26`, `SRC-DEEPAGENTS-DOCS-2026-11-26`, `SRC-APP-SPEC-2026-11-25` — epistemic tag: SOURCE_REPORTED.*


## Runtime model — open-source backend


The app’s AI backend is an open-source, open-weights model. No proprietary model serves as the app’s engine. Deep Agents is model-agnostic: any model that supports tool calling works — frontier APIs, open-weight models hosted on providers, and self-hosted models via Ollama, vLLM, or llama.cpp. The model is supplied by the caller when the agent is created; the harness does not dictate it.
- **Default model:** `Qwen/Qwen2.5-7B-Instruct` — an instruction-tuned 7B open-weights model (7.61B parameters, 131,072-token context, Apache License 2.0, ungated on Hugging Face), verified to exist on Hugging Face 2026-11-25. It plugs into the harness as the LangChain chat model. The card recommends serving with vLLM or Hugging Face Transformers.
- **Selection criteria (for the default or any replacement):** an instruction-tuned open-weights model suited to document reasoning, structured extraction, and checklist evaluation; a license permitting the app’s use (a permissive open license such as Apache 2.0); small enough to run in the app’s hosting (7B class); ungated on Hugging Face; and it must support tool calling, which the harness requires.
- **Pinning (build time).** The model is served from Hugging Face and pinned to an immutable commit SHA — never a floating branch or tag — the same rule as TOOL-GH-01 / gate A3. At build time the SHA is resolved and pinned via the TOOL-GH-01 flow (`pin_commit_sha` to resolve the ref, `verify_ref` to check it), recorded in the app configuration, and the app loads weights only at that pinned SHA. A tag may be used only as the input to the pin step; the app never loads weights by a branch name or a tag. The pinned commit SHA for this build is: *to be pinned at build time*. No SHA is stated here — none was resolved at writing time, and inventing one would violate the provenance rules.
- **The model is a reasoning engine only.** It never assigns VERIFIED_FACT; its outputs are SOURCE_REPORTED / GENERATED_ANALYSIS until a human reviews them. The governance precedence hierarchy (§4) places model preference last: the model never overrides policy, the AGENTS.md specification, a gate, a task contract, or a dispatch.

## Six interdiction triggers


The six deterministic interdiction triggers from the ICD203 document:
- INCOMPLETE_PROVENANCE
- SIMILARITY_IS_NOT_CORROBORATION
- MARKET_SIGNAL_IS_NOT_EVENT_EVIDENCE
- GENERATED_SUMMARY_IS_NOT_SOURCE_EVIDENCE
- PROHIBITED_CAUSAL_RELATIONSHIP

A trigger halts promotion of the affected claim until the provenance or epistemic defect is resolved. A claim a trigger fires on routes to quarantine or pending review, never to silent promotion. ## Deep Agents harness — the integration


Deep Agents is an open-source agent harness, an opinionated agent that runs out of the box, built on LangGraph. The repository is `langchain-ai/deepagents`, public, MIT License, created 2025-07-27. As read 2026-11-26 it reports 31,617 stars, 4,473 forks, and 4,935 commits. Its stated principles are: opinionated (defaults tuned for long-horizon, multi-step work), extensible (override or replace any piece without forking), model-agnostic (any model that supports tool calling), and production-ready (built on LangGraph with streaming, persistence, and checkpointing, plus tracing, evaluation, and deployment via LangSmith). The project states it was inspired by Claude Code.


The harness is assembled from three layers:


```


`┌───────────────────────────────────────────┐│  Deep Agents  (harness, defaults)          ││    ├─ PlanningMiddleware     (write_todos) ││    ├─ FilesystemMiddleware   (ls/read/…)   ││    ├─ SubAgentMiddleware     (task tool)   ││    ├─ SummarizationMiddleware (compaction) ││    ├─ AequitasGateMiddleware (18 gates)    ││    ├─ ProvenanceMiddleware   (source reg.) ││    └─ Neo4jContextMiddleware (SVG repo map)│├───────────────────────────────────────────┤│  LangGraph  (runtime)                      ││    persistence · streaming · interrupts    │├───────────────────────────────────────────┤│  LangChain  (building blocks)              ││    models · tools · prompts                │└───────────────────────────────────────────┘`
```


- **`create_deep_agent` returns a compiled LangGraph graph.** The entry point is a single function; the result is a `CompiledStateGraph`, so streaming, checkpointing, interrupts, and time-travel apply, and any `CompiledStateGraph` can itself be passed in as a sub-agent. The harness is the highest-level abstraction in the LangChain stack: LangGraph is the graph runtime, LangChain’s `create_agent` is a minimal harness on top of it, and Deep Agents is the more opinionated harness on top of `create_agent`, with filesystem, sub-agents, context management, and skills bundled in.
- **Middleware.** Each piece attaches tools and prompt instructions to the agent, and any piece can be overridden or removed. The built-in set is Planning, Filesystem, SubAgent, Summarization, plus Memory (AGENTS.md), Skills, and a human-in-the-loop interceptor. Muse / LIBERTAS adds three middleware of its own: the AequitasGateMiddleware (the 18 gates, deterministic), the ProvenanceMiddleware (registers source_id, source_locator, and retrieval_timestamp on every tool result), and the Neo4jContextMiddleware (injects the SVG repository map, §10).
- **Backends.** The filesystem is pluggable: in-memory (the default, ephemeral), local disk, a LangGraph-store-backed persistent backend, a composite of several, or a remote/sandboxed backend (Modal, Runloop, Daytona) — the sandboxed backends also add an `execute` tool for running code in an isolated sandbox. The Muse / LIBERTAS backend is the local repository filesystem (the app and library repositories) for working memory, with the Neo4j graph as the map. Large tool outputs are offloaded to files when they exceed the harness’s eviction threshold (about 20k tokens), so the context window does not balloon on one tool call.
- **Pinning.** The `deepagents` package is pinned to an immutable commit SHA via TOOL-GH-01, never a branch or tag. The observed HEAD at retrieval (2026-11-26T15:47:00Z) is `87f6080d9f3375e0b41aa07a71ce0a8f1027dd9a`; it is recorded here as the pin candidate and must be re-verified at build time with `pin_commit_sha` before the harness is installed. The package is MIT licensed.
- **Security posture — overridden, not adopted.** The Deep Agents README states a “trust the LLM” model: the agent can do anything its tools allow, and boundaries are enforced at the tool/sandbox level, not by expecting the model to self-police. Muse / LIBERTAS does not adopt that posture. Boundaries here are enforced by the deterministic AEQUITAS gates and by tool allow-lists, outside the model. The model never grades its own work, and no boundary relies on the model choosing to behave.

The parent runs the gate middleware on the report — provenance complete, epistemic tag present, no trigger fired — before using any claim from it. A report that fails a gate goes to quarantine, and the parent does not consume it.
- **Context isolation.** A subagent’s context window is its own. The parent receives only the final report, not the subagent’s full transcript. This keeps long-horizon work from blowing out the parent’s context window, and it keeps a subagent’s intermediate reasoning out of the evidentiary record — only the gated report enters it.
- **A subagent never promotes a claim.** Only human review assigns VERIFIED_FACT (gate E3). A subagent may propose, never promote. A subagent may not write to the graph, publish a post, or push to a repository; those are parent actions, gated and human-signed.

## Neo4j graph context — the repository map


The repository map is a Neo4j graph. It is the Spatial mode’s context: a map of the repositories the agent works in, with the files, the claims, and the sources laid out as nodes and edges. The agent does not navigate by it (navigation_suitability = 0); it orients by it.

- **SVG graph context.** For each task, a query extracts the relevant subgraph — the files, claims, and sources the task touches — and the subgraph is rendered as an SVG and injected into the agent’s context alongside the structured node/edge list. The SVG is the visual, human-inspectable form of the same subgraph; the structured list is the machine-readable form. The rendering is deterministic: the same query against the same graph state produces the same SVG bytes, so the SVG is reproducible evidence, not a rendering the model invented. The `graph` subagent (§9) produces the SVG; the Neo4jContextMiddleware injects it.
- **The graph never authorizes a mutation by itself.** Graph mutation is false for market and sentiment content, and any graph write goes through the AEQUITAS gates and human review (gate E3). The agent’s graph context is read-only by default; the `graph` subagent queries it, and writes are parent actions.
- **Build status.** The Neo4j Cypher migration is Phase 4 of the roadmap, and it is built only if the Human Supervisor asks. This document specifies the graph schema and the SVG context mechanism; the migration script itself is a Phase 4 build step, not part of this proposal. Nothing in this document authorizes building it.

## Deterministic evidence controls


The evidence controls are deterministic: they run as code, not as model judgment. The model does not grade its own work.
- **Provenance on everything.** Every source object carries a source_id, a stable source_locator, and a UTC retrieval_timestamp. A payload lacking any of the three is INCOMPLETE_PROVENANCE and fails the build. Every tool result and every subagent report is registered the same way before it is used.
- **Canonicalization and hashing.** Canonicalization follows RFC 8785 before SHA-256 hashing. Every stored claim carries its hash; a claim whose hash does not match its content is not used.
- **Epistemic tags.** SOURCE_REPORTED / GENERATED_ANALYSIS / VERIFIED_FACT. VERIFIED_FACT requires human review (gate E3). No silent epistemic upgrades are performed. A subagent’s output is GENERATED_ANALYSIS until gated.
- **Pinning.** All external code and weights are fetched only at pinned 40-hex commit SHAs through TOOL-GH-01 (the `deepagents` package, §8; the Qwen model weights, §3). Branch names are refused. The invariant is: commit_sha is the anchor; branch names are not.
- **Market and sentiment.** SENTIMENT_ONLY: market content is never event evidence and never authorizes a graph mutation. graph_mutation_authorized is false, human_review_required is true, and confidence_weight is 0.0.
- **No causal edges.** No causal edges are asserted. Claims from different source types are kept as separate nodes, never merged into one claim.
- **Gate middleware.** The AequitasGateMiddleware runs the 18 gates and the six interdiction triggers on every tool call, file write, subagent report, and claim promotion. A write that bypasses the gate fails. A report that fails a gate goes to quarantine.
- **Human-in-the-loop.** The harness’s interrupt mechanism is wired to gate E3 (human sign-off) and gate D2 (context vs. authorization separation). A tool call that needs human approval pauses; it does not proceed on the model’s say-so.

## Acceptance criteria


The integration and its artifacts must pass the 18-gate acceptance checklist, enforced by `tools/aequitas_gate_linter.py`. Each gate reports PASS, FAIL, or MANUAL. Gates D2 (context vs. authorization separation) and E3 (human sign-off) are MANUAL by design and are confirmed by a human, not by the scan.


Deep Agents-specific acceptance checks (proposed):
1. The harness loads with the pinned `deepagents` commit SHA, verified through TOOL-GH-01.
1. Every subagent has a registered task contract; a delegation without a contract fails before it starts.
1. Every subagent report carries provenance and an epistemic tag; a report without either is quarantined.
1. The Neo4j SVG repository map reproduces deterministically: the same query against the same graph state produces the same SVG bytes.
1. The gate middleware runs on every tool call and file write; a write that bypasses the gate fails.
1. The “trust the LLM” posture is not adopted: no boundary relies on the model self-policing.
